`get_lr`: three branches. Warm-up: `max_lr * (step + 1) / warmup_steps`. After `max_steps`: `min_lr`. Between: `ratio = (step - warmup) / (max_steps - warmup)`; `coeff = 0.5 * (1 + math.cos(math.pi * ratio))`; `min_lr + coeff * (max_lr - min_lr)`. `clip_grad_norm`: collect `p.grad` for the parameters where it is not None, `total = sqrt(sum((g ** 2).sum()))`, and if `total > max_norm` do `g.mul_(max_norm / (total + 1e-6))` for each gradient. Return `total` as a float.
---
Checkpoint: `torch.save({...}, path)` with `model.state_dict()`, `optimizer.state_dict()`, `step`, `config`, `torch.get_rng_state()` and `data_generator.get_state()`. Loading: `torch.load(path, weights_only=False)`, then `model.load_state_dict`, `optimizer.load_state_dict`, `torch.set_rng_state(ck["torch_rng"])`, `data_generator.set_state(ck["data_rng"])`. Return the dict.
---
`train_run`: build the optimizer and the generator first, then `if resume: start = load_checkpoint(...)["step"]`. In the loop, set `pg["lr"]` for every param group BEFORE the update, evaluate (when `step % eval_every == 0`) before the update, and save with `step + 1` after it. `stop_after` only shortens the loop (`end = min(stop_after, max_steps)`); the schedule still uses `max_steps`. Save a checkpoint when the loop is about to finish too. If resume differs from the uninterrupted run, the missing piece is almost always an RNG state or the optimizer state.
