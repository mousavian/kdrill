# Capstone: a queued, resumable two-worker run with a planted fault

## Concept

Everything in this course comes together in one run, the way a real
training job is set up:

- a **JobSet** of two DDP workers with stable DNS names (lessons 11, 14);
- submitted to a **Kueue** queue and admitted as one gang (lessons 15, 17);
- a **failure policy** that restarts the whole group when a worker dies
  (lessons 07, 13, 14);
- **checkpoints on a volume all workers share**, so a restarted group resumes
  instead of starting over (lessons 05, 06, 12);
- a final **model artifact** with metadata, consumed by another Job
  (lessons 05, 19).

The run has a **planted fault**: worker 1 crashes once at step 300 (exit
code 1, as if its node had a bad NIC). The `train` script remembers that it
has crashed by writing a marker next to the checkpoints (`FAIL_ONCE`), so a
correctly set up run crashes once, restarts, resumes from step 300 and
finishes. A run whose state does not survive the restart crashes again and
again. Nothing in this lesson is new; the skill is reading the symptoms and
finding which piece is missing.

## The situation

ResourceFlavor `default-flavor`, ClusterQueue `training-cq` (2 CPUs: one run
of two 1-CPU workers), LocalQueue `training`, and PVCs `checkpoints` and
`models` exist. JobSet `capstone` (2 workers, 900 steps, checkpoint every
100) was created from `manifests/capstone.yaml`. `manifests/sample.yaml`
samples text from `/models/capstone`. There are **four faults** in the
JobSet.

## Your task

JobSet `capstone`, still 2 workers of 1 CPU, 900 steps, child
`backoffLimit: 0` and the planted fault (`FAIL_AT_STEP=300`, `FAIL_RANK=1`,
`FAIL_ONCE=true`, `FAIL_EXIT_CODE=1`), must:

- go through the queue `training` (a Workload that is admitted and finishes);
- survive the crash with a group restart (`failurePolicy.maxRestarts` 1-5,
  `status.restarts` at least 1);
- keep its checkpoints (`CKPT_DIR`) on the PVC `checkpoints`, so that an
  attempt resumes at step 300 and the run ends `done` at step 900 on 2
  workers;
- write the model to `/models/capstone` (`MODEL_OUT`).

Then Job `sample` (from `manifests/sample.yaml`) completes, sampling from
`/models/capstone/model.pt`. Don't change the queues.

## Useful commands

    kubectl get jobset,workloads,pods
    kubectl get jobset capstone -o jsonpath='{.status}'; echo
    kubectl logs -l jobset.sigs.k8s.io/jobset-name=capstone --prefix | grep -E "resumed|starting|crash|lost|done"
    kubectl describe workload <name> | tail

The fixed run takes 1-2 minutes including the restart.

## On a real cluster

This is the shape of most production training on Kubernetes, scaled up:
hundreds of GPU workers in a JobSet (often generated by the Kubeflow Trainer),
Kueue quotas per team, checkpoints every N minutes to object storage, an
automatic restart budget for hardware faults, and a model pushed to a
registry at the end. The fine-tuning course continues from the model this
course produces.
